# ROU SPA 後台營運控制升級報告

更新日期：2026-10-03  
正式資料庫：Supabase `etiggwqxacnlrgokfsjt`  
正式網站：<https://www.rouspa.tw/>

## 本次目標

本次升級把既有後台補成可實際營運的門店系統，保留前台的米白、棕色與金色視覺，集中完成下列功能：

- 店主可設定每週及特殊日期營業時間，前台預約即時套用。
- 店主可預覽、備份及按期間重設相互關聯的營運資料。
- 非店主員工只能使用營運首頁、預約與日程、評價及自己的薪資績效。
- 顧客檔案可新增、修改、刪除／封存、恢復，並區分消費客人和會員。
- 店主可把預約改派給真正執行服務的技師，完成堂數、評價、收入及提成一併改按實際技師歸屬。
- 店主可為每位技師逐日排班，前台只提供當日實際上班且具備療程資格的技師與時段。
- 薪資與提成直接讀取人員檔案、實際服務記錄及結帳記錄，並可逐筆追查計算來源。
- 人員可獨立標記為在職、已離職或停用／未任職；離職後保留薪酬、服務與評價歷史。
- 後台互動增加細緻的網格、掃描線、光暈及鍵盤焦點效果，維持原有品牌色系。

## 1. 營業時間與休假

### 每週營業時間

店主可在「系統設定 → 門店資料與營業時間」分別設定星期日至星期六：

- 是否營業
- 開始時間
- 結束時間
- 跨夜營業，例如 10:00 至翌日 02:00

### 特殊日期

特殊日期會優先覆蓋每週規則，可設定：

- 當日休假
- 當日特別營業時間
- 節日延長營業
- 內部說明
- 恢復使用原本每週時間

後台首頁新增「今日營業／今日休假」即時卡片，店主可直接修改當日狀態。

### 前台同步

前台首頁在「預約體驗／查詢預約」按鈕下方直接顯示今日營業時間；當日休假時改為顯示「今日休假」，特殊日期說明也會同步出現。前台聯絡頁和營業時間顯示同樣讀取正式資料庫。公開預約空檔、建立預約及顧客自行改期均使用同一套營業時間規則。當日休假後不再產生新空檔，既有預約保持不變。

## 2. 資料重設與備份

「系統設定 → 資料重設」只向店主開放。可選擇今天、本星期、本月或全部期間，也可選擇下列範圍：

| 範圍 | 連動處理 |
| --- | --- |
| 預約、完成數與療程收款 | 預約、結帳、預約評價、管理憑證、預約操作記錄及相關儲值／套票／現金流水一起處理；已扣點數或堂數同步回復 |
| 商品訂單 | 訂單及明細、商品收款、訂單庫存異動一起處理，售出庫存回補 |
| 評價與匿名建議 | 清除所選期間建立的評價和匿名建議 |
| 薪資與工時 | 薪資結算、明細、工時、加班及薪資調整一起處理 |
| 門店支出 | 清除所選期間記錄的費用支出 |
| 全部營運記錄 | 組合以上範圍並依關聯順序處理 |

重設流程先顯示受影響筆數，再要求輸入 `RESET`。店主可選擇：

- 先下載 JSON 備份，再重設
- 不下載備份，直接重設

系統會保留會員檔案、儲值與套票購買記錄、員工與登入帳號、療程和商品主資料、庫存主資料、床位及門店設定。重設動作會寫入稽核記錄。

## 3. 員工角色與資料邊界

### 店主

`owner` 保持完整管理權限，可管理人員、帳號、薪酬、會員、收支、報表、目錄、營業時間及系統設定。

### 其他角色

資料庫強制所有非店主角色只能擁有：

- 營運首頁
- 預約與日程
- 評價（唯讀）
- 自己的薪資與績效

即使前端被修改，資料庫也會拒絕為非店主角色加入會員、收支、人事、商品或系統設定權限。

員工日程可查看全店安排以便協作，但顧客電話、管理憑證及私人內容會被遮蔽；員工不能修改或取消預約。員工可查看顧客公開資料和評價，不能管理評價、匿名建議或其他員工的薪資資料。

### 離職人員

人事檔案新增三種任職狀態：在職、已離職、停用／未任職。標記離職時必須填寫離職日期及原因；系統會停止官網接單、隱藏排班與休假編輯、停用後台登入，並在資料庫阻止重新啟用該帳號。服務、評價、薪資及稽核歷史不會刪除。

人事頁預設顯示在職與已離職人員；停用／未任職的舊示範資料收進單獨篩選。薪資頁會顯示在職人員、離職日在所選期間內或之後的人員，以及本期確實有服務、工時、商品提成或薪資調整的人員。離職員工可做最後薪資調整，但不能新增離職後加班。這也修正了 `王詩涵` 等舊示範人員在沒有任何本期記錄時仍出現在薪資試算的問題。

## 4. 顧客與會員檔案

顧客中心新增以下能力：

- 新增消費客人或會員
- 修改姓名、手機、電子郵件、會員等級及內部備註
- 依「全部／消費客人／會員」篩選
- 顯示已封存檔案
- 匯出包含類型及狀態的 CSV
- 刪除無營運歷史的檔案
- 有歷史資料時改為安全封存
- 恢復已封存檔案

消費客人儲值或購買套票後會自動升級為會員。曾封存的客人再次透過相同手機預約時，檔案會恢復使用，避免產生重複顧客。

## 5. 後台首頁與介面

- 今日營業狀態直接顯示於首頁。
- 非店主不顯示營收、會員、低庫存等不屬於其職責的指標。
- 評價加入獨立導覽入口。
- 後台背景改為與前台一致的米白、棕色、金色系。
- 增加低透明網格、移動掃描線、按鈕邊緣光和懸停光暈。
- 補強鍵盤焦點、窄螢幕版面及 `prefers-reduced-motion` 支援。

## 6. 實際服務技師與評價歸屬

後台預約卡新增「指定實際技師」。店主或具預約管理權限的人員可在顧客到店後改派技師，系統會驗證：

- 人員仍在職且未封存
- 人員已啟用該療程資格
- 未完成療程符合當日排班、休假與時段衝突規則
- 必須填寫更換原因

預約目前的 `staff_id` 是最終的實際服務技師，也是完成堂數、評價、療程收入及提成的唯一歸屬來源。顧客原先選擇的技師不會遺失；系統會保留首次預約技師、每次前後技師、原因、操作人、操作時間及提成變化。

已完成療程仍可修正實際技師，方便處理現場臨時換手或補登。若療程已結帳，系統會立即按新技師的個人提成或療程覆蓋比例重算該筆提成。顧客已送出的評價透過預約關聯自動改歸實際技師，無需複製或重建評價。

## 7. 每日技師排班與前台預約

「人員與排班」新增每日排班。指定日期設定優先於每週模板，可選擇：

- 上班並設定開始、結束時間
- 當日休班
- 填寫早班、晚班、臨時排休等備註
- 刪除每日覆蓋，恢復該星期的固定排班

每日排班與前台預約使用同一個資料庫判斷。前台只顯示同時符合門店營業時間、技師每日／每週排班、技師休假、療程資格、床位及既有預約衝突的時段。顧客自行改期亦使用相同規則。

若縮短或關閉某日排班會排除既有未完成預約，系統會拒絕儲存，要求先在預約頁改派技師或改期，避免顧客預約被靜默破壞。

## 8. 薪資與提成完整聯動

薪資試算與人員系統使用相同的員工 ID、職稱、聘僱類型、薪酬方式、基本薪酬及個人提成設定。療程統計拆分為：

| 指標 | 計算規則 |
| --- | --- |
| 完成堂數 | 實際技師名下所有已完成療程 |
| 已結帳堂數 | 已完成、已結帳且未退款，會計入療程薪酬及提成 |
| 待結帳堂數 | 已完成但尚未結帳，顯示提醒但暫不計薪 |
| 退款堂數 | 已退款完成療程，不計入應付提成 |
| 服務收入／提成 | 只取實際技師名下已結帳且未退款的記錄 |
| 商品訂單／提成 | 只取該人員名下已付款的商品訂單 |

按堂計酬以「已結帳堂數」計算，避免單純修改完成狀態就產生薪資。療程改派後，舊技師的堂數、收入、評價與提成會移出，新技師會接收同一筆來源；薪資明細不再維護一套與人員或訂單分離的手工數字。

薪資頁新增「查看計算來源」，可逐筆查看療程、預約編號、結帳／待結帳／退款狀態、收入、提成、評價數、商品訂單、加班及薪資調整。CSV 和 Excel 亦增加完成、已結帳、待結帳、退款、商品訂單及薪酬基準欄位。

## 9. 資料庫安全

- 新增營業時間及特殊日期資料表，啟用 Row Level Security。
- 管理函數只授權已登入角色，並在函數內再次驗證店主權限。
- 資料重設要求店主權限、精確確認字串及資料庫交易鎖。
- 顧客刪除要求精確確認字串 `DELETE`。
- 公開端只取得官網顯示和預約所需的營業資訊。
- 所有權限、營業時間及重設操作均由資料庫規則保護。
- 每日排班及技師改派只允許已登入且具相應管理權限的角色執行；資料表本身不開放前端直接讀寫。
- 技師改派以交易鎖保護並寫入獨立歷史表，避免同時操作造成歸屬或提成不一致。
- 匿名 API 對新排班表、改派記錄及管理函數均被拒絕，前台只能透過既有安全預約函數取得可用時段。

## 12. 日常操作建議

1. 先在「系統設定」核對每週營業時間。
2. 遇到店休、節日或延長營業，在首頁直接設定今日狀態。
3. 新客先建立為「消費客人」；辦理儲值或套票後系統會自動轉為會員。
4. 重設資料前先查看影響筆數，正式資料建議選擇「先儲存備份，再重設」。
5. 員工離職時在人事檔案選擇「已離職」，填寫離職日期及原因；系統會自動停用接單與登入並保留歷史薪酬。封存只用於重複或不應繼續顯示的檔案。
6. 每日開店前在人員頁確認當日技師排班；臨時代班使用「每日排班」覆蓋，不必修改長期每週設定。
7. 顧客到店後若改由另一位技師服務，先在預約卡按「指定實際技師」，再完成與結帳，確保評價和提成落到正確人員。
8. 薪資結算前先處理「完成待結帳」記錄，再從「查看計算來源」抽查療程與商品明細。
