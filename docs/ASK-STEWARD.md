# 問管家部署與驗證

使用入口：登入營運後台，右下角「問管家」。完整使用規則統一維護在 [ROU_SPA_OPERATING_MANUAL.md](../ROU_SPA_OPERATING_MANUAL.md)。

## 服務端設定

Vercel Production Secret `KIMI_API_KEY` 保存已提供的 Kimi Code 訂閱密鑰。密鑰不進入 Vite、公開環境變數、GitHub、手冊或回覆。改環境變數後需要新部署。

預設使用 `https://api.kimi.com/coding/v1`、模型 `k3`、`high` 推理，真實識別 `ROU-SPA-Steward/1.0`。已用訂閱密鑰成功完成實際請求；不以其他工具身份繞過認證。這與 Moonshot 開放平台的地址、密鑰及模型配置不同。若之後要更換服務，僅由維護者在服務端修改 `KIMI_BASE_URL`、`KIMI_MODEL`、`KIMI_REASONING_EFFORT`，不得由瀏覽器傳入。

## 資料與權限

`api/ask-steward.js` 驗證 Supabase 的真實登入與最新角色，用原使用者 JWT 查詢白名單讀取接口；不使用 service-role 金鑰。資料聚合及欄位裁剪在 `server/steward-context.mjs`，金額轉新台幣元、百分比轉百分數，工時保留分鐘。

員工僅能詢問被授權的營運首頁、日程、評價與自己的薪資出勤。當前頁面每次重新查詢；私人客戶聯絡資料、存取 token、評論／備註自由文字與精確打卡位置不納入自動摘要。模型呼叫前與釋出回答前都重驗角色，權限變更會拒絕舊摘要或答案。模型沒有工具或寫入業務資料的能力。

完整手冊打包到 Vercel Function，並每次讀入。對話只保留在瀏覽器目前帳號記憶體；服務端不保存提問或答案。使用者自行輸入的文字與所引用對話會送交 Kimi，面板應避免輸入密碼與私人資料。API 回覆只取可見回答，不傳出供應商推理內容。

## 配額與故障

遷移 `202610080011_ai_steward_limits.sql` 保存私人帳號計數，不保存問答。無參數 `spa_ai_reserve_request()` 原子預留：店主每日100、其他有效人員每日40，每整分鐘3次，以伺服器台灣時間換日。成功預留後失敗或關閉不退次數。未部署配額、手冊載入失敗、無效身份或非授權頁面都停止呼叫模型。

供應商 401／403 顯示服務認證問題，不把它誤當成本網站角色撤銷；429 區分門店帳號限額與供應商訂閱限制。其餘故障以可重試中文訊息呈現，不回傳原始錯誤、密鑰或私密資料。

## 規則維護

規則／UI／資料映射改動後核對並更新唯一手冊，再執行 `node scripts/check-operating-manual.mjs --record` 保存人工核對後的指紋。`npm test`、`npm run build` 都檢查來源與手冊一致；工具不能代替人工理解或自動編寫規則。

驗證包括真實 PostgreSQL 配額、API 身份／頁面／撤銷／錯誤、摘要映射與隱私，以及桌面手機互動。實際部署與線上回答需另外驗證，不以 mock 測試代替。
