# 柔療髮浴｜薪資數字對帳報告

更新日期：2026-10-04

## 一、這次發現的問題

「本期加扣」記錄有成功儲存，但舊版薪資函數只讀取 `計入日期 = 查詢起始日` 的資料。當記錄日期落在起訖範圍內、但不等於起始日，就會出現在部分資料中而沒有進入薪資結算。

另一個容易誤會的地方是「指定客獎金」：它屬於抽成，應顯示在「抽成 → 指定」，不屬於「加班／加扣」。獎金、津貼與扣款才會進入加扣欄。

## 二、修正後的日期與分類規則

所有薪資來源統一按目前選擇的起日和迄日計算：

| 來源 | 日期依據 | 歸屬 |
| --- | --- | --- |
| 核准出勤 | 出勤日期 | 本薪、提成資格 |
| 核准加班 | 加班日期 | 加班費 |
| 一般獎金 | 計入日期 | 加班／加扣 |
| 津貼 | 計入日期 | 加班／加扣 |
| 扣款 | 計入日期 | 加班／加扣，作為減項 |
| 手動指定客獎金 | 計入日期 | 抽成／指定 |
| 預約服務 | 營業日期，且完成、結帳、未退款 | 服務收入、堂數、服務分鐘、提成 |
| POS 服務／商品 | 收款日期，且訂單已付款 | 服務或商品業績與提成 |

## 三、結算公式

每位人員的應發金額使用同一條公式：

```text
應發合計
= 本薪
+ 服務提成
+ 商品提成
+ 指定客獎金（自動比例 + 手動指定客獎金）
+ 加班費
+ 其他獎金
+ 津貼
- 扣款
```

內部金額以整數分保存，畫面以 NT$ 元顯示；百分比以基點保存；時間以分鐘保存。最終應發最低為 0。薪資明細會用同一組欄位重新加總並顯示差額，正確時差額為 NT$0。

## 五、參考文件中的兩處說明差異

參考 DOCX 自身有兩處不一致：段落寫「滿 35 出勤小時／第 36 服務小時」，詳細表格、公式及 HTML 頁面寫「滿 40 小時／41 小時起」。系統採用詳細表格與 HTML 的 40 小時版本。

承攬制度另有「自帶客 50%」及「滿 5 年可申請 50% 承攬」說明。這不是所有承攬人員的統一預設比例，因此系統沒有自動套用；可在對應職稱與承攬類型的提成階梯中設為 50%，或以指定客規則處理。建立正式承攬人員前，應按書面約定確認採用哪一種。

## 六、頁面對帳能力

薪資明細現在同時顯示：

- 應發公式及公式差額
- 實際套用的職稱 × 聘僱薪資設定
- 每筆加扣來源及計入日期
- 每筆核准加班
- 每筆核准出勤及計算工時
- 已完成預約、POS 服務、商品銷售和收款快照提成

儲存加扣項後，系統會重新讀取所選薪資版本與日期範圍，不再保留舊的試算結果。

## 七、正式資料對帳結果

正式資料庫以 2026-10-01 至 2026-10-05 試算，林雅芳的結果為：

## 八、自動驗證

回歸測試已加入以下檢查：

1. 加扣記錄只要計入日期落在所選範圍內，就必須同時出現在來源清單及薪資預覽。
2. 薪資明細必須返回加扣和出勤來源記錄。
3. 每一列 `應發合計` 必須嚴格等於所有顯示項目相加減後的結果。
4. 字型涵蓋、目錄、日期範圍、預約狀態、資料庫、員工權限、帳號登入與營運後台測試全部通過。
