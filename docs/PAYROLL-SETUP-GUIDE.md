# ROU SPA 薪資與提成設定操作手冊

更新日期：2026-10-04  
適用系統：ROU SPA 後台「人員與排班」及「薪資與提成」  
使用對象：店主（Owner）

## 1. 這套薪資系統如何運作

薪資資料不是另一份獨立名單。每一筆薪資都直接綁定同一位人員的 ID，並從以下資料自動彙整：

1. 「人員與排班」中的薪酬基準、基本薪酬、個人提成和聘僱類型。
2. 預約目前指定的實際服務技師。
3. 已完成、已結帳且未退款的療程。
4. 已付款商品訂單中指定的銷售人員。
5. 已核准的一般工時及加班記錄。
6. 店主手動加入的獎金、津貼、扣款及指定客獎金。
7. 所選薪資規則版本中的加班倍率及階梯提成。

目前的總額公式為：

```text
應發合計
= 本薪
+ 療程提成
+ 商品提成
+ 指定獎金
+ 加班費
+ 其他獎金
+ 津貼
- 扣款
```

如果扣款高於所有應發項目，畫面最低顯示為 NT$0，不會顯示負薪資。超出部分應另行核對，不會自動帶到下一期。

## 2. 第一次設定的正確順序

建議依照以下順序完成，避免薪資數字無法追溯：

1. 在「人員與排班」建立或打開員工檔案。
2. 設定聘僱類型、薪酬基準、基本薪酬和療程提成。
3. 確認該員工可提供的療程。
4. 在「薪資與提成」建立適用的薪資規則版本。
5. 核對加班倍率；有明確制度後才建立階梯提成。
6. 確認本期所有完成療程均已結帳，退款也已正確登記。
7. 登錄本期加班及加扣項。
8. 先儲存草稿並抽查來源，再匯出 CSV 或 XLSX。
9. 確認無誤後按「確認結算並鎖定」。

## 3. 人員檔案中的薪資設定

位置：`後台 → 人員與排班 → 選擇人員 → 編輯檔案`

### 3.1 聘僱類型

| 選項 | 用途 | 影響 |
| --- | --- | --- |
| 全職 | 正職人員 | 使用薪資規則中「全職」對應的加班倍率 |
| 兼職 | 部分工時人員 | 使用薪資規則中「兼職」對應的加班倍率 |

聘僱類型本身不決定月薪、時薪或按堂薪酬；實際計薪方式由「薪酬基準」決定。

### 3.2 薪酬基準

| 選項 | 「基本薪酬 NT$」應填內容 | 本薪計算方式 |
| --- | --- | --- |
| 月薪 | 每月固定薪資，例如 `36000` | 所選期間直接計入完整基本薪酬 |
| 時薪 | 每小時薪資，例如 `200` | 時薪 × 本期已核准一般工時分鐘 ÷ 60 |
| 每堂薪酬 | 每一堂已結帳療程的固定薪酬，例如 `600` | 每堂薪酬 × 已完成、已結帳且未退款堂數 |

#### 月薪的重要限制

目前月薪不會自動依到職日、離職日、請假或不足月比例折算。只要該員工應出現在所選期間，系統就會計入完整月薪。

因此月薪結算建議每次選擇完整月份。如果員工月中到職、月中離職或有其他需要折算的情況，請先自行算出差額，再用「新增加扣項 → 扣款」調整，並在說明中寫明計算方式。

#### 時薪的重要限制

時薪本薪只讀取狀態為「已核准」的一般工時記錄，並扣除休息分鐘。目前後台尚未提供一般工時／打卡記錄的操作介面；如果資料庫中沒有核准工時，時薪人員的本薪會顯示 NT$0。

在正式使用時薪制前，應先補齊一般工時登錄與核准流程；加班記錄不能代替一般工時。

#### 每堂薪酬的重要限制

只有同時符合以下條件的療程才計入按堂本薪：

- 預約狀態為已完成；
- 已完成結帳；
- 尚未退款；
- 預約目前的實際技師是該員工。

單純把預約改成「已完成」但尚未結帳，會列在「完成待結帳」，不會先計入按堂薪酬。

### 3.3 療程提成 %

這是員工個人預設療程提成，例如輸入 `5` 代表 5%。

沒有適用階梯提成時，結帳會優先使用該療程對該技師設定的覆蓋比例；如果沒有療程覆蓋比例，才使用人員檔案中的個人提成。

目前個人療程提成的結帳公式為：

```text
單筆療程提成
= max(0, 該筆療程收入 - 該筆養生茶金額) × 提成比例
```

例如療程收入 NT$1,100、養生茶金額 NT$100、個人提成 5%，該筆預設提成為：

```text
(1,100 - 100) × 5% = NT$50
```

如果後續更換實際服務技師，系統會按新技師的比例重算已結帳療程的提成，評價和完成堂數也會改歸新技師。

### 3.4 任職狀態與薪資

| 狀態 | 薪資行為 |
| --- | --- |
| 在職 | 正常顯示本薪、提成、加班及調整項 |
| 已離職 | 保留薪酬設定和歷史薪資；可加入最後結算調整，不能新增離職後加班 |
| 停用／未任職 | 沒有本期記錄時不進入薪資試算 |

離職人員會在包含離職日的期間保留薪資，也會在有實際服務、工時、商品提成或薪資調整的歷史期間顯示。

## 4. 薪資頁日期範圍

位置：`後台 → 薪資與提成`

頁面上方的開始日期及結束日期共同決定本次試算範圍。日期依台灣營業日計算，包含開始日和結束日。

建議月薪結算使用完整月份，例如：

```text
開始日期：2026-10-01
結束日期：2026-10-31
```

需要特別注意：

- 月薪不會因只選 7 天而自動變成四分之一。
- 加班警示會把所選範圍的加班分鐘與「每月上限」比較，因此月薪結算應以一個月為單位。
- 加扣項綁定「開始日期」。如果先在 `2026-10-01` 建立調整，之後把開始日期改成 `2026-10-02`，該調整不會出現在新範圍內。
- 同一組開始日期與結束日期只能有一份結算記錄。

## 5. 薪資表每一欄的意思

### 5.1 頁面上的主要欄位

| 欄位 | 意思 | 資料來源 |
| --- | --- | --- |
| 員工／來源 | 員工、任職狀態、職稱、薪酬方式、個人提成、離職日 | 人員檔案 |
| 完成 | 實際技師名下所有已完成療程數 | 預約 |
| 已結 | 已完成、已結帳、未退款的療程數 | 預約＋結帳 |
| 待結 | 已完成但尚未結帳的療程數 | 預約 |
| 本薪 | 月薪、核准時薪或按堂本薪 | 人員檔案＋工時／已結帳堂數 |
| 服務業績 | 已完成、已結帳、未退款療程的收入 | 結帳 |
| 療程提成 | 階梯提成或各筆結帳儲存的技師提成 | 規則＋結帳 |
| 商品提成 | 商品階梯提成或商品訂單儲存的銷售提成 | 規則＋POS 訂單 |
| 指定獎金 | 店主手動加入的指定客獎金 | 薪資加扣項 |
| 加班費 | 核准加班分鐘按聘僱類型及加班類型計算 | 加班記錄＋薪資規則 |
| 獎金／津貼 | 其他獎金與津貼的合計 | 薪資加扣項 |
| 扣款 | 本期人工扣款 | 薪資加扣項 |
| 應發 | 所有加項扣除扣款後的總額，最低為 0 | 系統計算 |

「完成／已結／待結」按此順序顯示。例如 `15 / 13 / 2` 代表完成 15 堂，其中 13 堂已結帳並進入薪資，另外 2 堂仍待結帳。

### 5.2 CSV／XLSX 額外欄位

匯出檔還包括：

- 任職狀態及離職日；
- 聘僱類型及薪酬基準；
- 退款堂數；
- 服務分鐘；
- 商品訂單數及商品業績；
- 加班分鐘；
- 其他獎金、津貼和扣款的分開金額；
- 加班上限警示；
- 使用的規則版本和加班倍率。

## 6. 查看計算來源

在員工姓名下按「查看計算來源」，可以抽查：

- 每一筆完成療程；
- 預約編號及營業日期；
- 結帳、待結帳或退款狀態；
- 該筆收入和提成；
- 與預約關聯的評價數；
- 計入的商品訂單；
- 本期加班及薪資調整來源。

建議在正式鎖定前至少抽查：

1. 堂數最多的員工；
2. 本期有改派技師的預約；
3. 本期有退款的預約；
4. 本期有離職或到職折算的人員；
5. 本期有加班或手動扣款的人員。

## 7. 薪資規則版本

位置：`薪資與提成 → 建立新版本`

薪資規則使用版本管理。建立新版本時，舊版本會儲存供歷史結算查閱；新版本會複製上一版本的加班倍率和階梯提成，再由店主修改。

### 7.1 版本名稱

用來辨識規則用途，建議包含年份和變更原因，例如：

```text
2026-10 正式薪資規則
2027 基本薪資調整版
```

### 7.2 生效日

表示這份規則開始適用的日期。建議設定在薪資期間的第一天，並在新期間開始前核對完成。

### 7.3 月薪換算時薪除數

只用於月薪人員的加班時薪基數換算，不會改變月薪本身。

```text
月薪加班時薪基數
=（月薪＋可納入的固定提成）÷ 月薪換算時薪除數
```

系統目前預設除數為 `240`。這是可配置數字，應由店主依正式薪酬制度及專業薪資意見確認。

### 7.4 時薪基數包含固定提成

| 選項 | 月薪人員加班時薪基數 |
| --- | --- |
| 包含 | 月薪＋療程提成＋指定獎金，再除以換算除數 |
| 不包含 | 只用月薪除以換算除數 |

目前「固定提成」在系統公式中只包括療程提成和指定獎金，不包括商品提成、其他獎金、津貼或扣款。

這個選項只影響月薪人員。時薪人員直接以人員檔案中的時薪計算加班基數；按堂薪酬人員目前不會自動產生加班費。

### 7.5 一般月上限、勞資會議月上限、季度上限

| 設定 | 目前用途 |
| --- | --- |
| 一般月上限 | 超過後顯示一般月上限警示 |
| 勞資會議月上限 | 超過後顯示較高層級警示 |
| 季度上限 | 儲存於規則及匯出檔；目前試算頁尚未自動產生季度累計警示 |

目前預設分別是 46、54、138 小時。這些是系統初始設定，不代表系統替代勞動法規或專業薪資判斷；正式使用前應依門店所在地、聘僱契約和最新法規確認。

## 8. 加班倍率

位置：`薪資與提成 → 編輯倍率與階梯提成 → 加班倍率`

每一列由四個條件組成：

| 欄位 | 意思 |
| --- | --- |
| 聘僱 | 全職或兼職 |
| 類型 | 平日延長工時、休息日出勤、國定／特別休假、例假日出勤 |
| 分鐘區間 | 該倍率套用在第幾分鐘到第幾分鐘 |
| 倍率 % | `134` 代表 1.34 倍，`167` 代表 1.67 倍，`200` 代表 2 倍 |

分鐘區間按累計加班分鐘切段。例如同一類型設定：

| 分鐘區間 | 倍率 |
| --- | --- |
| 0–120 | 134% |
| 120–240 | 167% |

如果登錄 180 分鐘，前 120 分鐘按 134%，後 60 分鐘按 167%。

系統初始規則內建的倍率如下。這些數字只是目前資料庫的初始設定；實際使用時，以後台所選規則版本顯示的內容為準。

| 聘僱 | 加班類型 | 分鐘區間 | 初始倍率 |
| --- | --- | ---: | ---: |
| 全職／兼職 | 平日延長工時 | 0–120 | 134% |
| 全職／兼職 | 平日延長工時 | 120–720 | 167% |
| 全職／兼職 | 休息日出勤 | 0–120 | 134% |
| 全職／兼職 | 休息日出勤 | 120–480 | 167% |
| 全職／兼職 | 休息日出勤 | 480–720 | 267% |
| 全職 | 國定／特別休假 | 0–480 | 100% |
| 全職 | 國定／特別休假 | 480–600 | 134% |
| 全職 | 國定／特別休假 | 600–720 | 167% |
| 兼職 | 國定／特別休假 | 0–480 | 200% |
| 兼職 | 國定／特別休假 | 480–600 | 134% |
| 兼職 | 國定／特別休假 | 600–720 | 167% |
| 全職 | 例假日出勤 | 0–480 | 100% |
| 全職 | 例假日出勤 | 480–720 | 200% |
| 兼職 | 例假日出勤 | 0–720 | 200% |

### 加班費範例

假設月薪 NT$36,000、換算除數 240、不包含提成，加班時薪基數為：

```text
36,000 ÷ 240 = NT$150／小時
```

若平日延長工時 180 分鐘，前 120 分鐘 134%、後 60 分鐘 167%：

```text
前 2 小時：150 × 2 × 1.34 = NT$402
後 1 小時：150 × 1 × 1.67 = NT$250.50
本次加班費：約 NT$652.50
```

系統會按所有符合區間加總後四捨五入到分。

不要讓同一聘僱類型和加班類型的分鐘區間重疊或留下空缺，否則可能重複計算或漏算。修改正式倍率前，建議先建立新規則版本，不要直接改動已在使用的制度。

## 9. 提成階梯

位置：`薪資與提成 → 編輯倍率與階梯提成 → 提成階梯`

沒有任何適用階梯時，系統使用結帳時儲存的個人／療程提成。有適用階梯時，階梯比例會取代個人提成來計算該期間的總提成。

### 9.1 指標

| 指標 | 起點／終點的單位 | 提成基礎 |
| --- | --- | --- |
| 服務分鐘 | 分鐘 | 本期服務業績 |
| 服務堂數 | 已結帳堂數 | 本期服務業績 |
| 服務業績 NT$ | 新台幣 | 本期服務業績 |
| 商品業績 NT$ | 新台幣 | 本期商品業績 |

服務分鐘、服務堂數和服務業績三種服務指標最終都是把符合的提成百分比乘以「服務業績」，不是按分鐘或堂數直接發固定金額。

### 9.2 起點與終點

- 起點包含在該級距內。
- 終點不包含在該級距內。
- 終點留空代表該起點以上都適用。
- 系統從符合條件的級距中選取最高門檻。

例如以服務業績設定：

| 起點 | 終點 | 提成 |
| ---: | ---: | ---: |
| 0 | 50,000 | 3% |
| 50,000 | 100,000 | 5% |
| 100,000 | 留空 | 7% |

本期服務業績 NT$80,000 時，療程提成為：

```text
80,000 × 5% = NT$4,000
```

### 9.3 目前設定階梯時的注意事項

目前版本會在所有符合的服務階梯中按「起點數值最高」選一列。分鐘、堂數和金額的數值不能直接比較，因此同一個規則版本不要混用「服務分鐘／服務堂數／服務業績」三種服務指標。請選擇其中一種作為門店唯一的療程階梯依據。

商品業績階梯可以與一種服務階梯並存，兩者分別計算。

階梯療程提成目前直接用完整服務業績乘以階梯比例；它不會像個人預設提成一樣先扣除養生茶金額。建立階梯前應先確認這正是門店想要的制度。

## 10. 登錄加班

位置：`薪資與提成 → 登錄加班`

需要填寫：

1. 員工；
2. 加班日期；
3. 加班類型；
4. 實際加班分鐘；
5. 原因。

只有在職且未封存人員可以新增加班。一次可輸入 1 至 720 分鐘。儲存後會直接進入該日期所在的薪資試算。

請根據實際出勤性質選對類型。類型選錯，即使分鐘正確，也會套用錯誤倍率。

## 11. 新增加扣項

位置：`薪資與提成 → 新增加扣項`

| 類型 | 用途 | 對應欄位 |
| --- | --- | --- |
| 獎金 | 績效獎金、臨時獎勵等 | 其他獎金 |
| 津貼 | 交通、餐費或其他津貼 | 津貼 |
| 扣款 | 到離職折算、請假或經確認的其他扣項 | 扣款 |
| 指定客獎金 | 顧客指定技師的獎勵 | 指定獎金 |

指定客人數會統計供查詢，但系統不會自動把指定客人數乘以固定金額；指定客獎金必須由店主在這裡手動輸入。

金額只能輸入正數。選擇「扣款」時也輸入正數，系統會在應發合計中自動減去。

說明應寫得可稽核，例如：

```text
10 月交通津貼
10/15 新客指定獎金 3 人 × NT$200
10/20 離職月薪折算差額
```

離職員工仍可加入最後結算的獎金、津貼、扣款或指定獎金。

## 12. 商品提成

商品訂單結帳時，如果訂單明細指定了銷售員工，系統會把商品明細金額乘以該員工的個人提成比例，並把結果儲存到訂單明細。

如果薪資規則中設定了「商品業績 NT$」階梯，則本期商品提成改為：

```text
本期商品業績 × 符合的商品階梯比例
```

沒有指定銷售員工的商品不會產生員工商品提成。

## 13. 草稿、鎖定與重開

### 儲存草稿

儲存當下試算快照，但仍可繼續修改預約結帳、加班、調整項或規則，再次儲存會更新同一期間草稿。

### 確認結算並鎖定

把所選日期、規則版本、人員資料、薪酬條件和計算結果儲存為正式快照。鎖定後不能直接覆蓋。

### 重開結算

需要填寫重開原因。系統會記錄操作人、時間和原因，然後把結算恢復成草稿。修改完成後應重新檢查並再次鎖定。

建議流程：

```text
處理待結帳療程
→ 核對退款與實際技師
→ 登錄加班及加扣項
→ 儲存草稿
→ 查看計算來源
→ 匯出 XLSX 複核
→ 確認結算並鎖定
```

## 14. 建議的初始配置

在薪酬制度尚未完全確認前，建議採用最容易複核的方式：

1. 為每位員工明確選擇月薪、時薪或每堂薪酬。
2. 先只使用個人療程提成，不建立階梯提成。
3. 將每種加班倍率交由會計或薪資專業人員確認。
4. 月薪人員每次按完整自然月結算。
5. 月中到職、離職或請假折算暫時用有說明的加扣項處理。
6. 指定客獎金以手動調整方式記錄，說明人數和單價。
7. 時薪人員在一般工時登錄功能補齊前，不要直接鎖定為正式薪資。
8. 每次變更制度都建立新版本，不修改已經鎖定的歷史結果。

## 16. 目前系統仍需注意的事項

以下是目前版本的實際行為，使用時不要假設系統已經自動處理：

1. 月薪不會自動按到職、離職、請假或日期範圍折算。
2. 一般工時／打卡尚無後台登錄介面，時薪本薪依賴資料庫中已有的核准工時。
3. 指定客獎金不會按指定客人數自動產生。
4. 季度加班上限已儲存，但尚未自動累計並顯示季度警示。
5. 服務階梯不要混用分鐘、堂數和金額三種指標。
6. 階梯療程提成按完整服務業績計算，不先扣養生茶金額。
7. 按堂薪酬人員目前沒有自動加班時薪基數。
8. 薪資系統提供計算與追溯工具，正式制度和倍率仍應依合約、會計意見及適用法規確認。
